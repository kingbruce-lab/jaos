# 京奥智库知识进化首期验收（2026-08-01）

## 已实现

知识进化首期已经形成持久化、可审计但绝不自动发布的复核流程：

1. 创始人登记已经发布、当前、定稿且原件完整的维护资料基线；
2. 管理员手工启动复核，或夜间任务按资料周期建立到期复核；
3. 服务端在权限过滤后生成并保存候选、证据、冲突和披露状态；
4. 创始人逐候选批准内部纳入、批准对外披露或拒绝；
5. 全部候选处理后生成确定性变更计划；
6. 创始人关闭复核，系统记录下次到期日但不推进资料截止线；
7. 新版资料经独立发布流程成为 `current` 后，创始人才能更新维护基线。

一次性 `POST /v1/evolution/digest` 继续保留为“不保存的临时检查”，不属于正式复核记录。

## 硬门槛

- 调用者必须经过服务端会话鉴权，角色和密级不能由请求自报；
- 基线、候选和后继文档必须通过当前状态、定稿、原件 SHA-256、项目归属和页码证据检查；
- 未执行的提案不作为项目成果；
- 当前资料冲突会阻断候选决策和变更计划；
- 对外候选必须由创始人单独批准披露；
- 候选决策和生成计划时会重新检查来源，防止审核后内容被替换；
- 高密级资料对低权限管理员隐藏，包含数量侧信道；
- 关闭复核、生成计划和更新基线使用不同的精确确认短语；
- 所有自动任务均保持 `automatic_publication=false`。

## 明确未实现

- 在真实内容运营责任人缺位时替公司作出业务判断；
- 绕过 `candidate → current` 发布审批直接更新维护基线。
