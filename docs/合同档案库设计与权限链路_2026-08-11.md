# 京奥智库合同档案库设计与权限链路（2026-08-11）

## 1. 目标

合同档案库与普通项目知识库隔离，用于安全保存、审核、查阅和本地检索合同原件。首期支持扫描 PDF、PDF、DOC、DOCM、DOCX。所有合同必须人工逐份审核后才能检索，不能批量确认或批量调级。

## 2. 固定分类与 NAS 目录

| 分类 | 固定密级 | 可查阅账号 | NAS 目录 |
|---|---:|---|---|
| 行政合同 | L4 核心敏感资料 | 密级上限 L4、L5 | `合同档案库/行政合同/L4` |
| 人事合同 | L4 核心敏感资料 | 密级上限 L4、L5 | `合同档案库/人事合同/L4` |
| 业务合同 | L4 核心敏感资料 | 密级上限 L4、L5 | `合同档案库/业务合同/L4` |
| 总办合同 | L5 公司最高机密 | 仅密级上限 L5 | `合同档案库/总办合同/L5` |

目录、分类和密级由服务端固定映射，前端不能提交任意路径或降低密级。放错分类或密级目录的文件不会入库，而是生成 `contract_layout_invalid` 待处理问题。

## 3. 入库与解析链路

1. 已授权员工在 Web 合同档案库选择其可见分类并上传 PDF 或 Word 原件；也允许授权人员直接将文件放入上述固定 NAS 目录。
2. 服务端使用随机临时文件流式接收，限制文件大小，采用原子方式落盘，不覆盖同名原件。
3. 系统将资料角色强制设为 `contract`，密级强制设为分类对应的 L4 或 L5，状态强制为 `candidate`。
4. 普通 PDF 直接提取分页文字；扫描 PDF 在 NAS 本地逐页渲染并使用 RapidOCR 识别，保留原始页码；Word 提取正文，并由 LibreOffice 生成引用版 PDF。
5. OCR 或引用版生成失败会明确显示失败状态，不允许把空白解析结果当成已完成资料确认。
6. 资料管理员或创始人逐份预览、确认或拒绝；只有已确认资料进入合同列表和检索。

## 4. 查阅与检索安全链路

1. 会话身份在服务端解析，任何请求不得自报角色或密级。
2. 先校验账号密级，再执行数据库查询；无权账号不会得到文件数量、标题、相似度或“是否存在”的侧信道。
3. 普通知识检索、智能写作、项目列表和项目详情均在 SQL 召回前排除四个合同域。
4. 合同检索只接受固定分类，采用本地元数据、全文和 OCR 文字的确定性检索，不调用 Embedding、Rerank 或 LLM。
5. 打开原件前再次执行用户密级、文档密级、原件在线状态和 SHA-256 完整性校验；浏览器不获得 NAS 原始路径。
6. 合同上传、列表、搜索、预览、审批、拒绝和密级变更均写入审计日志。

## 5. 出网边界

- 合同全文、OCR 文本、文件名、搜索词和命中片段均不发送到 OriginGame 网关或任何云模型。
- L4、L5 文档不建立云端向量索引；索引任务会清除误建的高密向量。
- L5 继承并强化 L4 的全部限制，不存在任何可开启的合同出网开关。

## 6. 验收项目

- L3 账号看不到合同档案库入口，直接调用 API 返回 403。
- L4 账号只看见行政、人事、业务合同，不能枚举或访问总办合同。
- L5 账号可看见四类合同。
- 同一查询在普通 AI 资料检索中不返回合同，在合同档案库本地检索中按权限返回。
- 扫描 PDF OCR 后的命中引用到正确页码；OCR 失败不得审批。
- 直接放入 NAS 正确目录的合同进入审核；错误目录生成问题，不会自动降级。
- 合同搜索期间网关调用次数为 0；数据库中 L4/L5 合同向量数为 0。
- 普通 NAS 账号不得绕过 Web 读取合同目录；NAS 超级管理员仍保留系统级最高权限，其操作由组织制度约束。
