# 2026-09-04 登录阻塞修复

## 原因

- 备份在复制、校验大体积素材期间保留 `file_blobs` 的数据库读事务。
- 周期扫描每次启动都执行 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`；即使列已存在，也会申请排他锁。事务先锁住 `users`，再等待备份释放 `file_blobs`，导致登录和健康检查排队、连接池耗尽。
- 资料治理查询同时连接项目全部文件、文件分块和衍生文件，产生乘法式中间结果。现场同项目文件关联会展开约 72 万行，API 进程占用接近 3 GiB 上限，并使用交换空间。

## 修改

- 数据库初始化先查询系统目录，仅添加缺失列、索引和约束；正常周期运行不执行 DDL 或数据更新。增加数据库锁等待和连接池等待上限。
- 备份和原件校验用短事务获取元数据快照，在文件复制、哈希期间释放数据库连接。校验结果不覆盖并发改变的文件路径。
- 治理查询的集合关联改用分批加载，保留现有筛选和权限规则。
- 数据库暂不可用时返回不包含 SQL 或连接信息的 503；登录请求 20 秒超时并显示明确提示，不改变上传超时设置。
