# 京奥智库 NAS 首次上线

适用设备：飞牛 NAS EVO4、N150、16GB 内存、128GB 系统盘、单块 8TB 东芝 N300。

当前目标是内部 5 人试点，不是正式发布。单盘和无 UPS 按已确认口径允许进入测试，但预检会持续显示提醒。

## 当前状态（2026-07-27）

首轮技术部署已完成。公司局域网内打开：

```text
http://jadj-nas.local:3000/
```

如果主机名暂时无法解析，可使用当前地址：

```text
http://192.168.2.53:3000/
```

当前地址由 DHCP 分配，可能变化；推荐日常使用主机名，并在路由器中为 NAS
设置 DHCP 地址保留。系统目前只有创始人试点账号，首次登录后立即在
Web 左下角点击“改密”。不要沿用 NAS 超级管理员密码，也不要把智库密码
发到群聊或文档。

以下步骤保留为从零重装或升级时的标准流程。

## 上线前只需要准备五项

1. 京奥资料在 NAS 上的团队文件夹绝对路径。
2. 备份目录路径。测试期可以暂时同盘，但不算灾难恢复备份。
3. 两个不少于 16 位且互不相同的密码：
   - PostgreSQL 数据库密码；
   - 首次创始人管理员密码。
4. 确认 NAS 内网的 3000 端口未被其他应用占用。
5. 在资料根目录建立 `99_AI入库待审核`，员工上传到这里，智库容器只读挂载。

密码只写入 NAS 上未提交的 `.env`，不要发到微信、文档或 Codex 对话。

Codex 交付的 `jingao-copilot-nas-*.zip` 不包含账号密码、API Key、数据库或知识文件原件。上传 NAS 后先解压，再按本说明填写本机 `.env`。

## 第一步：填写 NAS 配置

在项目目录复制示例配置：

```bash
cp .env.example .env
```

至少填写：

```text
JINGAO_DB_PASSWORD=
JINGAO_BOOTSTRAP_PASSWORD=
JINGAO_KNOWLEDGE_PATH=
JINGAO_BACKUP_PATH=
JINGAO_INBOX_SCAN_INTERVAL_SECONDS=900
JINGAO_INBOX_SETTLE_SECONDS=120
```

试点阶段保持：

```text
JINGAO_EMBEDDING_ENABLED=false
JINGAO_EMBEDDING_L3_ENABLED=false
```

已暴露的旧模型测试 Key 不得写入 NAS。

## 第二步：运行只读预检

```bash
sh scripts/nas-preflight.sh
```

工具只检查，不安装、不启动、不改文件、不改权限，也不会显示密码。

结果分为：

- `通过`：该项满足试点要求；
- `提醒`：可以继续试点，但不能视为正式发布通过；
- `失败`：必须先处理，不能启动部署。

把完整预检结果交给 Codex 复核。失败项清零后，再进入构建和启动。

## 第三步：部署后验收

部署完成后必须依次完成：

1. PostgreSQL/pgvector 实机启动；
2. 文件与数据库备份；
3. 隔离恢复演练；
4. 技术探针评测；真实资料足够时应形成 120 项页码引用探针，加上
   15 项拒答和 15 项权限探针，共 150 项；
5. 5 人并发测试；
6. 原页预览抽查；
7. 权限越界探测。
8. 向 `99_AI入库待审核` 放入一份无敏感内容的测试文件，等待 120 秒后确认自动出现在入库审核页；再次复制同内容文件，确认不会新增重复文档。

资料真实性、员工权限分配、`current` 晋升、L3 出网和正式发布仍需创始人确认。
