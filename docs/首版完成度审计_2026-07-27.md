# 京奥智库首版完成度审计（2026-07-27）

## 审计结论

京奥智库已经达到“可进入真实资料试点准备”的技术状态，但尚未达到“正式业务验收完成”。

当前可用的技术闭环包括：

- 7 个 NAS 容器持续运行：数据库、Agent、Web、待审核扫描、原件对账、每日备份、Uptime Kuma；
- 本地账号登录、检索前权限过滤、确定性检索、候选/当前/历史口径、页码引用和受控原页预览；
- 待审核资料扫描、SHA-256 去重、元数据建议、创始人确认、受控发布与旧版降级；
- Brief 到提案骨架、相似案例、风险提示和可编辑 PPTX；
- PostgreSQL 完整备份、原件封入、独立临时实例恢复、引用哈希抽查和恢复会话失效；
- Codex 查询 Skill、局域网 Web 入口、运行监控和 Runbook。

当前不能把“合成资料技术通过”等同于“京奥真实知识库已验收”。真实公司资料、员工账号和云模型开关仍受创始人授权门控制。

## 状态口径

| 状态 | 含义 |
|---|---|
| 已完成 | 技术实现和现有测试证据均已通过 |
| 待业务验收 | 技术能力已具备，但必须用创始人批准的真实资料或真实员工验证 |
| 部分完成 | 已完成可安全推进的部分，仍有明确缺口 |
| 待决策 | 继续执行会改变真实资料、权限、出网或外部系统状态，需要创始人确认 |
| 二期 | 实施计划明确不在首期 |

## 本轮技术审计修复

1. 将关键词和向量两条召回路径都改为 SQL 查询阶段先过滤用户密级、项目密级和知识状态；越权分块不会进入评分函数。
2. 新增“越权分块不得进入关键词评分”的回归测试；后端自动化测试更新为 61/61。
3. NAS 运行验收脚本从“只打印信息”升级为明确的通过/失败判定，覆盖 7 个服务、4 个 HTTP 状态、最新备份、备份原件完整性和 4 个出网安全开关。
4. 将实施计划更新为 v1.7，按实装情况把 kkFileView 调整为 Agent 受控 PDF 流式预览。

## 进入真实试点前仍需创始人确认

1. 首批资料：建议先选 3 个而非一次上 20 个；逐份确认真实性、密级、定稿和 current/历史口径。
2. 员工账号：提供 5 人的登录名、显示名、角色和密级上限；另确认 break-glass 管理员保管方式。
3. 云端开关：是否先只开 L1-L2 的 LLM，Embedding 暂缓；L3/L4 继续关闭。
4. 第二备份：指定移动硬盘、另一台电脑或另一块存储作为 NAS 外备份目标。
5. 告警目标：指定一个飞书群机器人或其他接收渠道。

以上五项未确认前，系统保持“合成资料、本地确定性检索、无真实账号、无云端出网”的安全状态。
