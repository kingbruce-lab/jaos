## NAS 部署前置

- 本云环境需要可以访问 NAS 的维护连接及身份；当前没有已配置的 SSH 密钥、fnOS 入口或登录绑定。
- 当前云环境对 `192.168.2.53:22` 和 `:3000` 连接被拒绝，`jadj-nas.local` 不能解析；公网域名请求在网络代理 CONNECT 阶段被拒绝，未到达生产应用。
- 上一次已记录的生产版本为 `1.4.9`，本次尚未读取当前运行版本、磁盘、备份或就绪状态。

## 连接恢复后的执行顺序

1. 读取并保存实际运行版本、当前及上一源码指针、镜像身份、服务与磁盘状态；确认最新封存备份完整可校验，且运行 `.env` 已存在。
2. 将对应干净提交和 `jaos-v1.5.0` 标签的 NAS ZIP 上传到新的版本目录，校验 ZIP 的 SHA-256 及包内 `SHA256SUMS`。
3. 按 `docs/发布与回滚.md` 执行新版本的 `scripts/deploy-nas-runtime.sh`、`manage.sh build`，确认构建退出状态后再执行 `manage.sh start`。
4. 检查 `manage.sh status`、内部和公网 Web、Agent `/readyz`、实际项目页面、移动布局及运行脚本验收结果；不得以单独首页 200 代替全部验收。
5. 保留旧源码和镜像；出现阻断问题时按既有 `manage.sh rollback` 回退。
6. 使用临时 SSH 维护时，按 Runbook 移除临时身份并关闭 SSH，再复核服务。

不要把密码、私钥、运行 `.env`、数据库或业务资料放入 Git 或发布包。已有生产配置和出网开关必须保留。
