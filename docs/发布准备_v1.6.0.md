# v1.6.0 财务分析桌面与移动端改版发布准备

本文件记录发布前验证，不代表已经在 NAS 部署或完成线上验收。

## 变更与兼容性

- 统一财务各级页面的导航、公司切换、卡片、表单和空状态；银行批次、公司编码改为目录与独立明细，支持搜索、筛选及返回位置保留。
- 同步完成手机竖屏、横屏、吸顶页签、完整金额、44px 触控区域和 16px 输入字号适配。
- 以最新 `main` 的 v1.5.1 为基线，保留其对资金健康、上周收入前十、上周支出前十、上周风险预警及集团内部划转板块的移除。
- 保留银行原始证据、财务确认、用途复核、权限及统计口径；账外现金仍独立核算，编码账簿仍包含历史年度。
- 防止公司、口径、年度及批次切换时过期请求回写；表单失败后保留输入，支持重试。
- 增加有权限校验的只读银行批次元数据接口，使年度检索可以打开不在近期列表中的历史批次。
- 数据库结构、Python/Node 依赖和锁文件未改变。Agent 源码有变化，部署时必须构建新版 Agent 与 Web，不能直接复用旧 Agent 镜像。

## NAS 连接核验

- 当前云环境未绑定 NAS／fnOS／SSH 部署身份或可用维护入口。
- `192.168.2.53:22`、`:3000` 连接被拒绝，`jadj-nas.local` 无法解析；公网域名请求在代理 CONNECT 阶段返回 403，未到达生产应用。
- 仓库没有配置 `.github` 自动部署工作流；推送代码不代表 NAS 已更新。
- 最新仓库验收文档记录线上版本为 v1.5.1，并记录容量与完整备份时效告警。这是历史记录，本次未独立读取当前运行版本、磁盘或备份状态。

## 连接恢复后的发布顺序

1. 读取实际运行版本、当前及上一源码指针、镜像、服务、磁盘和备份状态；按 Runbook 处理预检结果，确认升级所需空间及有效备份，保留原有运行 `.env`。
2. 将干净提交及 `jaos-v1.6.0` 标签对应的 NAS ZIP 上传到新的版本目录，校验归档 SHA-256 和包内 `SHA256SUMS`。
3. 按 `docs/发布与回滚.md` 执行新版本的 `scripts/deploy-nas-runtime.sh`，再执行 `manage.sh build`；确认构建退出状态后执行 `manage.sh start`。
4. 检查内部和公网首页、运行版本、Agent `/readyz`、服务状态、财务及项目关键页面与手机布局。分别验证新版 Web 和 Agent，不能以单独首页 200 代替完整验收。
5. 保留旧源码、镜像和配置；发生阻断问题时按 `manage.sh rollback` 回退，并记录实际发布与验收结果。
6. 如使用临时 SSH 维护，按 Runbook 移除临时身份并关闭 SSH，再复核服务。

不要把密码、私钥、运行 `.env`、数据库或业务资料放入 Git 或发布包；保留生产配置和出网开关。
