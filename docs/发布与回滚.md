# JAOS 发布与回滚

## 1. 版本规则

- 版本号读取仓库根目录 `VERSION`，使用语义化版本，例如 `1.0.0`。
- Git 标签使用 `jaos-v1.0.0`。
- NAS 发布包命名为 `jaos-v1.0.0-nas-YYYYMMDD-HHMMSS.zip`。
- 发布包必须包含版本号、Git 提交号、构建时间和 `SHA256SUMS`；不包含 `.env`、密钥、数据库或业务资料。
- 生产运行目录保留 `CURRENT-SOURCE.txt` 与 `PREVIOUS-SOURCE.txt`，因此任何新发布都能退回上一套源码和镜像。

## 2. 发布前门槛

在 Windows 开发机运行：

```powershell
pnpm test
cd agent
.\.venv\Scripts\python.exe -m pytest -q
cd ..
.\scripts\package-nas.ps1
```

只有前端构建、前端测试和 Agent 全量测试全部通过后才能发布。工作区有未提交改动时，发布包会明确标记为 `dirty`；正式发布必须使用干净提交和对应标签。

## 3. NAS 发布

1. 将 ZIP 解压到新的只读发布目录，不覆盖旧目录。
2. 执行新版本中的 `scripts/deploy-nas-runtime.sh`。
3. 执行：

```sh
sudo /vol1/@team/京奥智库/00_部署/jingao-runtime/manage.sh build
sudo /vol1/@team/京奥智库/00_部署/jingao-runtime/manage.sh build-status
sudo /vol1/@team/京奥智库/00_部署/jingao-runtime/manage.sh start
sudo /vol1/@team/京奥智库/00_部署/jingao-runtime/manage.sh status
```

4. 检查公网 `/`、内网 `/`、Agent `/readyz`、数据库迁移结果和关键业务页面。

发布脚本在切换前会把原 `CURRENT-SOURCE.txt` 写入 `PREVIOUS-SOURCE.txt`。旧源码目录和旧镜像不得在验收前删除。

## 4. 一键回滚

新版本出现阻断问题时执行：

```sh
sudo /vol1/@team/京奥智库/00_部署/jingao-runtime/manage.sh rollback
```

回滚会：

1. 校验上一版本目录存在；
2. 重新安装上一版本 Compose 和运行脚本；
3. 重建上一版本 Agent/Web 镜像；
4. 启动并输出服务状态；
5. 把被回滚版本自动变为下一次可恢复的上一版本。

数据库迁移必须保持向后兼容，只允许首期采用“新增表、增加带默认值的列、扩大兼容范围”等可回退变更；禁止发布会让上一版本无法读取数据库的破坏性迁移。

## 5. 发布记录

每次生产发布至少记录：版本号、Git 提交、发布时间、操作者、备份包、数据库迁移摘要、验收结果和是否发生回滚。运行目录的 `RELEASE-HISTORY.log` 会追加机器可读记录，业务验收结论另写入发布记录文档。
